## STEP 5: DETAILED SPLICING OUTLINES

### **PRIMARY SPLICING EXAMPLE: IoT and Mobile Towers**

#### **SPLICE A: "IoT & Streaming Data Architecture for Mobile Tower Networks"**

**Position:** Cloud & DevOps → Data Pipelines  
**Tone:** Technical infrastructure excellence

**Problem Statement:**
A major African telecom operator needed real-time visibility into 10,000+ mobile tower operations across geographically distributed regions. Legacy systems couldn't handle the data velocity, and manual collection caused 48-hour reporting lag.

**Solution Architecture:**
- **Ingestion:** MQTT brokers at regional hubs collecting ~2 million messages/min from towers
- **Processing:** Databricks ETL pipelines on Azure Data Lake for real-time analytics
- **Storage:** Multi-layered data lake (bronze/silver/gold) for different access patterns
- **Analytics:** Self-service analytics portal for network planners

**Technologies:**
- Azure Data Lake Storage Gen2
- Databricks (Apache Spark)
- MQTT 3.1.1 & Kafka for message streaming
- Delta Lake for ACID transactions
- Python, Scala for ETL

**Outcomes:**
- **99.7% data delivery reliability** (SLA)
- **Real-time insights** (< 5-minute latency vs. 48 hours)
- **65% cost optimization** vs. proprietary tools
- **Foundation for ML models** on tower health prediction

**Metrics:**
- 2M events/minute processing capacity
- 50TB raw data/month ingestion
- 90% data quality score

**Client:** Major African Telecom Operator  
**Industry:** Telecommunications  
**Duration:** 8 months  
**Team:** 4 architects, 6 engineers

---

#### **SPLICE B: "Kubernetes-Driven Scalability for Telecom Operations"**

**Position:** Cloud & DevOps → Container Platform  
**Tone:** Enterprise operational reliability and performance

**Problem Statement:**
Mobile tower management applications were monolithic and slow to scale. Each new region required weeks of infrastructure provisioning. The operator needed rapid scaling to support new market entries.

**Solution Architecture:**
- **Multi-Region Clusters:** Kubernetes on AWS (3 regions) with automatic failover
- **Microservices:** Refactored alerting, provisioning, and billing services into 20+ containerized components
- **Scaling:** Horizontal pod autoscaling based on network events and request latency
- **Deployment:** GitOps-based CD with ArgoCD for declarative infrastructure

**Technologies:**
- Amazon EKS (Kubernetes 1.25+)
- Docker for containerization
- ArgoCD for GitOps
- Helm charts for package management
- Prometheus + Grafana for cluster observability

**Outcomes:**
- **3x throughput increase** on same infrastructure investment
- **Infrastructure provisioning reduced from weeks to hours**
- **Automatic failover capability** achieving 99.99% availability
- **50% infrastructure cost reduction** through right-sizing

**Metrics:**
- 50+ microservices running in production
- 20,000+ pod deployments/month
- < 500ms deployment propagation time

**Client:** Major African Telecom Operator  
**Industry:** Telecommunications  
**Duration:** 10 months  
**Team:** 3 platform architects, 5 DevOps engineers

### **SECONDARY SPLICING EXAMPLE: Automated Incident Management**

#### **SPLICE A: "Intelligent Incident Automation"**

**Position:** Observability & AIOps → Incident Response Automation  
**Tone:** Operational risk reduction and response speed

**Problem Statement:**
A telecom NOC was receiving 50,000+ alarms daily, but only 8% represented genuine incidents. Operators spent 70% of time filtering noise and finding relevant events.

**Solution:**
- **Intelligent Correlation:** Event enrichment, deduplication, and correlation rules
- **Runbook Automation:** Context-aware remediation scripts with human approval gates
- **Escalation Logic:** Time-based and severity-based escalation to senior engineers

**Outcomes:**
- **40% reduction** in manual incident handling
- **60% reduction** in false alarms through correlation
- **MTTR improved by 35%** through automated remediation

---

#### **SPLICE B: "ServiceNow Integration for IT Operations"**

**Position:** Service Desk & ITSM → ITSM Implementation  
**Tone:** Process standardization and governance

**Problem Statement:**
Network alarms were disconnected from the ITSM ticketing workflow, causing incidents to be handled manually outside official change/incident management.

**Solution:**
- **Alarm-to-Incident Bridge:** Microservice consuming alarm stream, auto-creating ServiceNow incidents
- **Workflow Automation:** Incident assignment, change scheduling, and communication automation
- **Compliance:** Full audit trail and SLA enforcement

**Outcomes:**
- **100% incident traceability** (regulatory compliance)
- **Incident lifecycle time reduced by 45%**
- **Standardized process** across global NOCs

## STEP 7: RISK & TONE CONSIDERATIONS

**For All Case Studies:**
1. **Lead with Risk Mitigation** — Frame solutions as reducing operational/financial/compliance risk
2. **Quantify Reliability** — Always include uptime %, reduction metrics, cost savings
3. **Emphasize Enterprise-Grade** — Mention SLAs, redundancy, failover, compliance
4. **Show Operational Excellence** — Reference 24/7 operations, follow-the-sun, proactive monitoring
5. **Highlight Expertise Depth** — Position Perception IT as trusted risk partner, not just vendor

**Example phrases:**
- "Eliminated single points of failure..."
- "Achieved 99.99% availability SLA..."
- "Reduced mean-time-to-recovery from X to Y..."
- "Ensured compliance with [regulatory framework]..."
